# Deterministic Music Semantics

MoL Keyboard applies music commands in one core-owned order on every target:

```text
input note
  -> octave shift and semitone transpose
  -> scale mapping
  -> chord expansion
  -> arpeggiator scheduling
  -> sustain or monophonic portamento
  -> voice allocation
```

The input adapter assigns a nonzero `gesture_id` to each press. The core stores
the notes produced for that gesture, so a later Note Off releases the stored
notes rather than recalculating them from current settings. Changing octave,
transpose, scale, or chord mode therefore affects only later gestures. A
duplicate active gesture is rejected diagnostically, and independent gestures
that resolve to the same pitch remain independently releasable.

## Keyboard, pitch, scales, and chords

The default physical map uses USB HID usages and covers MIDI 60 through 89
(C4--F6) in the documented 30-key layout. Operating-system key-repeat Note On
events are rejected by gesture ownership. Input adapters must map `Space` to
CC64 sustain and send `ALL_NOTES_OFF` when their input context is lost.

Octave shift is limited to -3 through +3 and transpose to -24 through +24.
Notes outside MIDI 0--127 do not allocate a voice and produce a music-error
event.

Scale mapping supports Chromatic, Major, Natural Minor, Major Pentatonic,
Minor Pentatonic, Blues, Dorian, and Mixolydian for all 12 tonics. The Down and
Up modes search only in their named direction. Nearest searches both directions
and resolves an equal-distance tie downward.

Chord expansion uses these semitone interval tables:

| Mode | Intervals |
|---|---|
| Off | 0 |
| Major | 0, 4, 7 |
| Minor | 0, 3, 7 |
| Sus2 | 0, 2, 7 |
| Sus4 | 0, 5, 7 |
| Dominant 7 | 0, 4, 7, 10 |
| Major 7 | 0, 4, 7, 11 |
| Minor 7 | 0, 3, 7, 10 |
| Power 5 | 0, 7 |
| Octave | 0, 12 |

Intervals above MIDI 127 are discarded. When there are fewer voices than
requested chord notes, the core steals the oldest active voice, breaking equal
age ties by voice slot.

## Sustain and portamento

Sustain accepts the continuous CC64 range 0.0--1.0 and uses 0.5 as the on
threshold. Note Off marks its gesture as pedal-held while sustain is on;
crossing below the threshold releases only gestures whose physical key is no
longer held. `ALL_NOTES_OFF` follows normal release semantics, while
`ALL_SOUND_OFF` immediately clears gestures, arpeggiator state, and voices.

Realtime MIDI 1.0 uses a bounded streaming parser with running status and
interleaved realtime-byte handling. Note On velocity zero is Note Off. CC1 maps
to the public 0--1 modulation parameter, CC64 remains continuous, pitch bend
maps its asymmetric 14-bit endpoints exactly to -1 and +1, and General MIDI
programs use the same built-in-preset mapping as `.mid` import. CC121 resets
sustain, pitch bend, and modulation; CC123 and CC120 map to All Notes Off and
All Sound Off. Every endpoint offers Omni or one-based Channel 1--16 filtering.
The parser and gesture stacks are fixed-capacity; a fifth overlapping Note On
for the same channel/note releases the oldest of the four retained gestures.

Portamento is monophonic and uses last-note priority. `LEGATO_ONLY` glides when
a previous monophonic gesture is still held; `ALWAYS` also glides from the last
target pitch after a separated note. The configured 0--2000 ms time is converted
to whole sample frames, and phase increment follows a linear per-sample ramp
without resetting oscillator phase. Chord and arpeggiator modes disable this
monophonic path.

## Transport, metronome, and arpeggiator

Transport is the only clock used by the metronome and arpeggiator. Tempo is
validated in the 30--300 BPM range and quantized to one milli-BPM. Step frame
positions are computed from their absolute rational value rather than by adding
rounded intervals, eliminating cumulative drift. The supported signatures are
2/4, 3/4, 4/4, 5/4, and 6/8. Metronome ticks are synthesized by the core and
the first beat of each bar is accented.

Arpeggiator modes are Up, Down, UpDown, DownUp, AsPlayed, and seeded
RandomDeterministic. Rates 1/4, 1/8, 1/8T, 1/16, 1/16T, and 1/32 correspond to
1, 2, 3, 4, 6, and 8 exact transport steps per quarter note. Gate is quantized
to one thousandth in the 0.05--1.0 range, and octave expansion accepts 1--4.
Stopping transport, switching mode, or sending `ALL_SOUND_OFF` releases the
arpeggiator voice.

## Conformance evidence

`mol_event_trace_conformance` compares an explicitly checked-in event digest
for a combined scale/chord/sustain/metronome/arpeggiator/portamento sequence.
Native and WebAssembly must both produce:

```text
events=35 hash=9e6cebee9d02f409 transport=50000 voices=0 gestures=0
```

The golden file is read-only during the test and is never regenerated by the
test runner. Property tests render the same scheduled sequence with unrelated
block partitions and require exact PCM, event, and final-state equality. A
fixed-seed 2,000-operation legal-command run checks finite output and eventual
gesture/voice release. The transport test evaluates every quarter-note boundary
through exactly two hours at 48 kHz/120 BPM, ending at frame 345,600,000 with
zero accumulated error.
